# timeout2h — emergency red button

Everything below is run from `PTCTCL/benchmarks/`.

## Stop everything, now

```bash
./stop_timeout2h.sh
```

Sets the STOP flag, kills the driver's whole process group, then kills the harness and the
benchmarked tools by name (they run in their own session, so the group kill alone misses
them). Safe to run twice.

## Stop politely (let the current benchmark finish)

```bash
./stop_timeout2h.sh --soft
```

Drops `results/timeout2h/STOP`. The driver checks for it before every benchmark, so it exits
before starting the next one. The run already in progress keeps going — up to 2 hours.

## Just look

```bash
./stop_timeout2h.sh --status
```

## If the scripts are gone / you want to do it by hand

```bash
touch results/timeout2h/STOP                                  # stop it starting anything new
kill -KILL -- "-$(cat results/timeout2h/timeout2h.pgid)"      # kill the driver's process group
pkill -9 -f bench_ltsmin.py ; pkill -9 -x ptctlmc ; pkill -9 -x verifyta
```

The nuclear option, if you do not care what else dies:

```bash
pkill -9 -f 'run_timeout2h|bench_ltsmin|ptctlmc|verifyta'
```

## Resuming after a stop

```bash
rm results/timeout2h/STOP
setsid nohup ./run_timeout2h.sh > results/timeout2h/driver.log 2>&1 < /dev/null &
```

Nothing is lost and nothing is measured twice: `bench_ltsmin.py` seeds itself from the output
CSV and skips every `(model, tool, threads, rep)` that already has an `OK` / `TIMEOUT` /
`MEMOUT` row. A run that was killed mid-flight has no row, so it is simply redone.

## Files

| path | what it is |
|---|---|
| `driver.log` | the driver's own timeline: START/DONE per job, gate waits |
| `verifyta_2h.csv` / `.log` | phase 1 results (UPPAAL, 1 thread) |
| `ptctlmc_t<T>_c<C>_2h.csv` / `bench_t<T>_c<C>_2h.log` | phase 2 results, one pair per config |
| `worklist.tsv` | what gets run, generated by `../gen_timeout_sets.py` |
| `worklist.report.txt` | the same list in human form, with why each model is on it |
| `timeout2h.pid` / `.pgid` | driver pid and process group (removed on clean finish) |
| `STOP` | presence = stop before the next benchmark |
| `ptctl.enabled` | presence = phase 2 (ptctlmc) is allowed to start |

## The phase-2 gate

Phase 2 (ptctlmc) does not start until `results/timeout2h/ptctl.enabled` exists — the driver
polls for it once phase 1 has finished. To release it:

```bash
touch results/timeout2h/ptctl.enabled
```

To make sure phase 2 never runs, just leave the file absent; the driver gives up after 48 h
(`GATE_WAIT_MAX`) and exits with phase 1 complete.
